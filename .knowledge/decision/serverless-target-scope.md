---
id: decision:serverless-target-scope
type: decision
title: Initial Serverless Target Scope
---
Initial function-host support is AWS Lambda, Azure Functions, Google Cloud Run functions, and Vercel Go; Cloudflare Workers joined as a fifth target once its adapter probe passed.

```yaml
meaning_of_support:
  includes:
    - provider-ready application artifact or source bundle generated without editing application handlers
    - runtime startup or exported-handler adapter
    - local build and HTTP conformance verification
    - documented provider configuration and runtime limits
  excludes:
    - account login, credential storage, cloud resource provisioning, remote upload, domains, and traffic promotion
  reason: the framework can deterministically own application packaging and runtime compatibility; provider infrastructure remains operator state
initial_targets:
  aws_lambda:
    runtime: requirement:serverless-http-hosting through AWS Lambda Web Adapter
    entry: existing selected-backend main
    artifact: Linux bootstrap, production config, and OCI Dockerfile with pinned adapter
  azure_functions:
    runtime: requirement:serverless-http-hosting custom handler with HTTP forwarding
    entry: existing selected-backend main
    artifact: Linux handler, production launcher, host.json, and HTTP catch-all metadata
  google_cloud_run_functions:
    runtime: Go Functions Framework
    entry: generated by requirement:serverless-source-entrypoints
    artifact: staged source bundle for the provider build
  vercel_go:
    runtime: Vercel Go runtime
    entry: generated by requirement:serverless-source-entrypoints
    artifact: staged source bundle with one api handler
  cloudflare_workers:
    runtime: system:syumai-workers fetch-to-net/http adapter inside a Wasm module
    entry: generated by requirement:cloudflare-workers-build-target
    artifact: Wasm module, framework-owned loader, and wrangler.jsonc, compiled locally by TinyGo or host Go
status_language:
  shipped: runtime behavior and generated deployment artifact both pass acceptance
  committed: in this scope but one or more acceptance checks remain
  blocked: desired but an external or compiler compatibility gate has no passing path
  deferred: deliberately outside this scope
current:
  aws_lambda: shipped
  azure_functions: shipped
  google_cloud_run_functions: shipped
  vercel_go: shipped
  cloudflare_workers: shipped by requirement:cloudflare-workers-build-target on 2026-09-02, a generated stage having passed the requirement:cloudflare-workers-hosting conformance list under both compilers
outside_initial_scope:
  - DigitalOcean and OpenWhisk event ABIs
  - Netlify provider-specific functions
  - non-HTTP triggers on every provider
  - component-model hosts deferred by decision:wasi-http-deferred
selection_reason:
  - the four process and source targets preserve the selected nethttp or fasthttp backend through a process adapter or exported net/http handler; the Wasm target preserves nethttp only
  - each has a bounded generated artifact shape
  - none requires application handlers to adopt a provider event type
acceptance:
  - one target cannot be reported shipped because another target passed
  - generated files identify their target and pinned adapter contract
  - every target runs the shared HTTP conformance suite before its status becomes shipped
build_axes:
  target: lambda, azure-functions, google-cloud-run-functions, vercel-go, or cloudflare-workers
  backend: nethttp by default or fasthttp when data:project-config declares project.fasthttp; cloudflare-workers accepts nethttp only
  output: .pw/build/<target>/<backend>/ with deployment.json
  development: api:cli-dev never selects a deployment target
```
